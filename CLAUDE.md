# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

**SG Buddy** — локальная GUI-программа на NiceGUI. Читает DDL-схему Postgres, даёт
настроить запросы по каждой таблице и пишет настройки в `schema.json`. Из этих
настроек генерируются `query.sql` для sqlc и `*.proto` для gRPC — **генератор
`.proto` ещё не написан**.

Каталог репозитория называется `grpc_sqlc_gui_helper` (историческое имя), пакет —
`sgbuddy`, команда — `sgbuddy`.

## Команды

```bash
uv run sgbuddy                      # http://127.0.0.1:8080
uv run sgbuddy --native             # отдельным окном
uv run sgbuddy --no-show --port N   # без открытия браузера, для проверок
uv run pytest                       # тестов сейчас нет: tests/ пуст
```

Проверка «поднимается ли»: запустить с `--no-show` на свободном порту, дёрнуть
`curl` и погасить процесс — сервер сам не завершается.

## Архитектура

Поток данных линейный: `schema.sql` → `ddl.py` → модели в памяти → формы в
`app.py` → словарь настроек → `settings.py` → `schema.json`.

| Файл | Ответственность |
|---|---|
| `sgbuddy/ddl.py` | **Единственное место, знающее синтаксис SQL.** Разбор `CREATE TABLE` через sqlglot в `Table`/`Column`. Правился только аддитивно. |
| `sgbuddy/settings.py` | Формат `schema.json`: ключи-константы, чтение/запись, навигация по разделу `CRUD`, миграция старого формата. Ключи задаются здесь и только здесь. |
| `sgbuddy/query_gen.py` | Перевод настроек в `query.sql` для sqlc. Все правила перевода — в docstring модуля. Файл кладётся в папку схемы, рядом со `schema.json`; своего ключа с путём в настройках нет. |
| `sgbuddy/app.py` | Весь интерфейс: стили, мастер из трёх шагов, сайдбар таблиц и четыре формы (Create/Read/Update/Delete). |
| `sgbuddy/__main__.py` | Разбор аргументов и `ui.run`. |

### Состояние

Программа локальная и однопользовательская, поэтому состояние — модульные
синглтоны в `app.py`: `workspace` (выбранные пути, разобранные таблицы,
загруженные настройки) и четыре черновика форм `form`, `read_form`,
`update_form`, `delete_form`. Черновик живёт до нажатия «Добавить» и сбрасывается,
когда меняется таблица.

Вся перерисовка идёт через один `@ui.refreshable def wizard()`. Любая функция,
меняющая состояние, заканчивается `wizard.refresh()`. Обработчики `on_change` у
полей ввода этого **не делают** — иначе форма перерисовывалась бы на каждый
символ и теряла фокус. Перерисовка при вводе допустима только там, где от
значения зависит состав формы (аннотация `many` в Read, режим в Delete).

`workspace.reset()` обходит поля через `dataclasses.fields`, чтобы новое поле
сбрасывалось само; `reset_all()` дополнительно обнуляет все четыре черновика.

## Формат `schema.json`

Лежит рядом со `schema.sql`. Начинается со строк `//` (JSONC) — обычный
`json.loads` его не съест, читать только через `settings.load_settings`.

```
// Файл создан программой SG Buddy.
{
  "schema_folder_path": "...",   // всегда первые два ключа
  "save_proto_path": "...",
  "CRUD": {
    "dc.alias": {                // таблица целиком, с именем схемы
      "CREATE": [ { "Name": ..., "Query Annotation": ..., "columns": [...], "custom_query": ... } ],
      "READ": [], "UPDATE": [], "DELETE": []
    }
  }
}
```

Набор ключей внутри `columns` **разный у направлений**: у CREATE это
`column_value`, у READ — `show`/`where`/`where_optional`/`exact_where`,
у UPDATE — `set`/`set_value`/`where`/`where_optional`/`where_value`,
у DELETE — то же, но `set`/`set_value` пишутся только в режиме `SOFT DELETE`.

Правила, которые легко нарушить незаметно:

- **Незаполненное текстовое поле пишется как `null`**, не как `""`. Исключение —
  `column_value` в CREATE: там пустое поле означает «приходит параметром» и даёт
  `@имя_колонки`.
- **Имена запросов уникальны по всему файлу** (`_name_taken`), а не в пределах
  таблицы: sqlc не разрешит двойника нигде.
- **Разделы таблиц заводятся лениво** (`ensure_directions` только при записи,
  `entries_of`/`directions_of` при чтении). Иначе от простого просмотра в файл
  упали бы пустые блоки всех шестнадцати таблиц.
- **Старый плоский формат** (`CRUD -> CREATE -> [{Table: ...}]`) встречается на
  дисках. `migrate_crud` разносит его по таблицам при чтении — не убирать.
- Сгенерированные файлы (`.proto`, JSON) **затираются целиком без подтверждений**.
  Диалогов «файл существует» быть не должно; в интерфейсе про это сообщают
  фактом, а не предупреждением.

## Генерация

`render()` возвращает текст и список `Problem`. Запрос, который нельзя собрать
(нет колонок, `UPDATE` без изменяемых колонок, ссылка на несуществующую колонку),
**пропускается с объяснением**, а не роняет генерацию целиком; опасные, но
осмысленные случаи (удаление без `WHERE`) помечаются `fatal=False` и всё равно
попадают в файл. Интерфейс показывает эти строки под сводкой.

`RETURNING *` всегда идёт последним: `custom_query` существует ради
`ON CONFLICT ...`, а он в Postgres пишется до `RETURNING`.

Генерация берёт настройки **из памяти**, а не с диска, — несохранённые правки
тоже попадают в файл.

## Подводные камни

**Кнопки создавать только с `color=None`.** Quasar вешает на цветную кнопку класс
`text-primary` и красит текст через `adoptedStyleSheets`; перебить это из своей
таблицы стилей нельзя даже с `!important` и большей специфичностью. Без
`color=None` текст активной CRUD-кнопки сливается с её фоном.

**Выпадающие списки Quasar не открываются под браузерной автоматизацией** — меню
рендерится в портал, а панель браузера в сессии не отображается. Ветки, которые
зависят от выбора в списке (`many` в Read, `SOFT DELETE` в Delete), проверять
вызовом обработчиков напрямую:

```python
from sgbuddy import app
app.wizard.refresh = lambda *a, **k: None   # вне клиента перерисовывать нечего
app.workspace.tables = ...; app.workspace.settings = {}
app.read_form = app.ReadForm(table=..., annotation="many", ...)
app._submit_read(table)
```

**sqlglot нормализует `DEFAULT`**: `now()` разбирается в узел `CurrentTimestamp` и
печатается как `CURRENT_TIMESTAMP`, `false` — как `FALSE`. Позиции токенов для
восстановления исходного текста непригодны (у `now()` в мете только имя без
скобок, у `Boolean` меты нет). Поэтому `_default_sql` приводит результат к виду
из DDL через явную таблицу подстановки; выражения со строковым литералом не
трогает, иначе `DEFAULT 'Hi'` стало бы `'hi'`.

## Проверка изменений

Эталон — `test_data/tables_model/schema.sql`: 16 таблиц, схема `dc`, есть
`dc."user"` с `bigserial`, кавычками в имени и inline-constraints. Пользователь
принимает работу именно на нём. Лежащий рядом `schema.json` — рабочий артефакт,
его можно затирать и пересоздавать.

Менять интерфейс вслепую не стоит: поднять сервер на свободном порту и проверить
вычисленными стилями и текстом страницы через браузерные инструменты, а не
предполагать, что CSS применился.

## Стиль

Комментарии и docstring-и по-русски, объясняют **почему** так сделано, а не что
делает код. Пользователь ведёт переписывание по шагам и формулирует каждый шаг
сам — делать ровно названное и не проектировать следующие шаги вперёд.
